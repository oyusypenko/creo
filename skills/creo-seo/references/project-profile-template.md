# Project Profile Template

Template for the file generated by `/creo seo init` at `.claude/skills/creo-seo/creo-seo-{project_id}.md`. This file makes every subsequent `/creo seo *` command faster and more accurate by caching project-specific context.

## File location

```
.claude/skills/creo-seo/creo-seo-{project_id}.md
```

`{project_id}` comes from `.claude/project-config.md`. If absent, prompt for a short slug (e.g. "acme").

## How init builds it

Init reads the codebase and extracts:

| Source | Extract |
|--------|---------|
| `package.json` | Project name, Next.js version, SEO deps (next-seo, next-sitemap), i18n libs |
| `next.config.{js,ts,mjs}` | trailingSlash, output mode, images config, i18n locales, redirects |
| `app/` or `pages/` | Router type (App vs Pages), route tree |
| `**/page.tsx`, `**/page.mdx` | All static routes |
| `**/[param]/page.tsx` | Dynamic route patterns |
| `app/layout.tsx`, `app/**/layout.tsx` | Default metadata, OG defaults |
| `app/sitemap.ts`, `next-sitemap.config.js` | Sitemap strategy + base URL |
| `app/robots.ts`, `public/robots.txt` | Robots policy |
| `public/llms.txt` | llms.txt presence |
| `app/**/page.tsx` with `generateMetadata` | Per-route metadata patterns |
| Grep `application/ld+json` | Existing schema types |
| Grep `next/image` usage | Image optimization patterns |
| Env vars (`SITE_URL`, `NEXT_PUBLIC_*`) | Production domain |
| README.md first paragraphs | Business description hypothesis |
| `public/favicon.*`, `public/og-*.{jpg,png}` | Brand assets |

## Refresh strategy

- **Auto-refresh**: when `/creo seo init --refresh` is run explicitly
- **Partial-refresh**: `/creo seo init --pages` re-scans only the page inventory
- **Stale flag**: treat profile as stale if `updated` is > 30 days old OR if `package.json` or `next.config.*` have been modified since last update

## Consumer usage

Every `/creo seo *` command loads this file at startup (if it exists) and uses it to:

1. Skip redundant codebase scans (page inventory, router type, SEO deps)
2. Apply business-type-specific scoring weights
3. Pre-populate hreflang, OG defaults, brand asset paths
4. Reference detected gaps as starting points for the audit
5. Attribute findings to specific files without re-grepping
